选库规则

默认方式下本系统不执行 svn：提交动作与提交资格由目标代码库自己的提交细则负责， 这里的绑定用于「这条 bug 属于哪份代码」的判定（提交闸门 G3）与审查页展示。 只有在该仓库允许本系统代跑 svn 时才会真正用到下面的建分支逻辑。
1. 先查 product_repos 表：该 bug 的 产品 有绑定且 enabled=1 → 用产品仓库；
2. 没有绑定 → 回落到 .env 的全局 SVN_REPO_URL / SVN_TRUNK_PATH / SVN_BRANCH_ROOT；
3. 全局也没配 → branch / commit 直接报错并给出 bind-repo 命令；
4. 工作副本默认按产品独立（留空时自动分配 {{ global_repo.working_copy }}\p<产品ID>-<仓库哈希>）；但它是手工填的， 两个产品填同一个目录（共用一份 git 镜像）时不再互相隔离，必须并入同一条串行队列 —— 串行按目录划分，不按产品（见 AUTO_LOOP.md §5）；
5. 主干始终只读：AI 只能提交到 <仓库>/<分支根>/{{ forms.new.branch_prefix }}<禅道ID>。

新增 / 修改绑定

点右上「新增绑定」或某行的「编辑」，在弹窗里填写；保存后弹窗会自动关闭并刷新列表。

等价的命令行写法（Trae / 脚本用这个）：
python -m app.cli bind-repo <产品ID> <仓库地址> --name "产品名" --trunk-path /trunk/3.0 --working-copy <镜像目录>
省略的选项沿用库里已有值，不会把没填的列清空；python -m app.cli repos 查看每个产品实际生效的仓库。
